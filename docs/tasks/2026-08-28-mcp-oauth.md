# Hosted MCP OAuth and connected apps

## Outcome

Add the hosted Market Signal OAuth 2.1 authorization layer used by the MCP endpoint. A signed-in account can grant and revoke least-privilege access for a Claude, Codex, or other standards-compliant MCP client without sharing a password or API key.

## Scope

- Configure Better Auth 1.7.2 with JWT signing, the MCP OAuth provider, and the strict MCP 2026-07-28 Client ID Metadata Document (CIMD) profile.
- Bind every access token to the exact protected resource `https://signal.blyzr.com/mcp`.
- Support `reports:read`, `reports:create`, `price_watch:read`, and `price_watch:write`, plus `offline_access` for rotating refresh tokens.
- Keep anonymous Dynamic Client Registration disabled. Current Claude Code and Codex clients both discover CIMD automatically; disabling DCR avoids an unauthenticated registration-abuse surface.
- Add browser login continuation, an explicit consent page, and connected-app management.
- Add authoritative per-request checks for the user session, client, consent, audience, and granted scopes. Connected-app revocation must take effect on the next MCP request.
- Keep browser session cookies out of the MCP authentication path. The MCP resource accepts bearer access tokens only.
- Return 404 for hosted MCP surfaces unless node auth, hosted billing, and the canonical production origin are configured.

## Security decisions

- Authorization code + PKCE is required for public clients.
- Access tokens expire after 10 minutes. Refresh tokens rotate with no reuse overlap and expire after 30 days.
- The resource policy permits `offline_access` so Better Auth retains it on the audience-bound grant and performs refresh-token rotation. It is an authorization/continuity scope, not a tool permission; protected-resource discovery advertises only the four resource permissions.
- Better Auth's audience-bound MCP access token is a JWT rather than the PRD's preferred opaque token. Local JWT validation is followed by a database-backed client, consent, and session check on every MCP request, preserving immediate connected-app revocation.
- CIMD metadata fetches use the package's Node transport, which resolves once, rejects non-public addresses, pins the approved address, and refuses redirects.
- Consent copy states that `reports:create` consumes report quota and `price_watch:write` can consume monitoring credits.
- OAuth responses, consent pages, and account connection APIs are non-cacheable. Consent pages cannot be framed.

## Registration and package decision

- Production registration uses CIMD only. Claude Code and Codex both document automatic CIMD discovery. Anonymous DCR remains disabled.
- The standards conformance harness uses an explicitly pre-registered public test client in its isolated test database. Production has no anonymous registration endpoint.
- Stable package identities are pinned to `better-auth@1.7.2`, `@better-auth/mcp@1.7.2`, `@better-auth/oauth-provider@1.7.2`, `@better-auth/cimd@1.7.2`, and `jose@6.2.10`.
- Package source and executable probes verified RFC 8707 resources, exact audience-bound JWT issuance, S256-only PKCE, disabled DCR, CIMD discovery, rotating refresh-token family invalidation (including a real rotated-token replay), consent storage, revocation endpoints, and RFC 9728 metadata.
- CIMD uses the official Node transport and plugin limits: HTTPS only; resolve-once DNS; rejection of special-use addresses; connection pinning; no redirects; JSON content type; a 5 KiB body cap; a five-second timeout; bounded concurrency/rate/cache; and exact registered redirect matching.
- Consent identifies the client by the `client_id` URL and host. Remote names are visibly marked self-asserted and unverified; remote logos are never loaded.
- JWT signing is pinned to EdDSA/Ed25519 with `kid`-based JWKS rotation. The resource verifier pins EdDSA, exact-string audience, issuer, expiry, and at most 60 seconds of clock tolerance.
- A live grant requires a matching consent, linked client/resource, unexpired account session, and one active refresh token bound to the same user, client, session, resource, and scope set. Better Auth invalidates the whole refresh-token family on rotated-token replay; the next MCP request then fails the active-grant check even if its short JWT has time remaining.
- Workspace identity is always derived from the persisted user and workspace membership. No workspace claim supplied by a client is trusted.
